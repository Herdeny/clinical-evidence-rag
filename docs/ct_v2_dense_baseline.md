## 数据与运行设置

- 检索语料：data/v2/evidence.jsonl，238 条。
- 题目：data/v2/cases.dev.jsonl，32 道开发题；未读取或评测留出题。
- 编码模型：BAAI/bge-small-en-v1.5，使用 HuggingFaceEmbeddings；Notebook 保存的向量形状为 (238, 384)。
- 设备：本次摘要记录 cuda。
- 查询：Report 加 Question，英文检索前缀与 B0 相同；前缀通过编码对象配置。
- 当前源文件声明文档批量 8、查询批量 1，均归一化，文档无前缀。原始运行摘要未保存这两组编码 kwargs，不能将核验时的源码信息伪装成当次完整运行配置；后续运行应由脚本自动记录。
- 每题 Top-5，截取同一结果计算 K=1／3／5；评分信息未拼入查询。

每个指标先按题计算，再对 32 道题取平均；分母为该题的规范证据 ID 数或证据需求组数。指标不是医学回答准确率。

Group Recall@5：15 题完整覆盖、1 题部分覆盖、16 题零覆盖。screening_framework、missing_examination_purpose、multiple_nodule_assessment 等场景的标注需求在本轮 Top-5 中仍未命中；这是后续固定数据对照需要观察的现象，不预先归因或保证 BM25 能解决。

CUDA 本轮检索平均 4.0475 ms，中位数 3.1064 ms。范围为查询编码、相似度、排序及返回组装，包括首题；不含模型加载和文档编码，不代表 CPU、并发或多轮稳定性性能。

正式入口 run_retrieval_eval.py 已接通完整流程。当前输入路径以父目录启动为前提，从项目根目录启动会定位到重复的 clinical-evidence-rag 子目录。沿用既定设计，以脚本所在目录组织输入和结果路径，将装配流程放入 main()，并在后续运行配置中记录实际 encode_kwargs、query_encode_kwargs、向量维度及评测 K。这些是入口与记录收尾，不改变现有检索或评分算法，也不要求为此重跑已保存的基线实验。

后续先批量扩充并固定主要医学检索语料版本，再做向量／BM25／RRF 的正式对照；现有 238 条／32 题保留为回归集，复用逐题评测口径及返回结构，按数据版本和方法分开保存。模型、数据、查询模板与最终 K 的变化不可混入算法对照。

题目仍是助手生成的 AI 初标，未经独立人工或医生复核。当前无生成回答、临床有效性、用药、多模态、留出题或 MIRAGE 对标成绩；完整项目的验收目标保持不变。v1 与 v2 数据不同，不能把两次分数差直接当成算法升降。
